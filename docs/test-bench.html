5 · tel: link whose text number DIFFERS from the href

Key case: two distinct items are expected, no deduplication. This lets the user choose which number to dial — it is intentional, not a bug. Deduplication only collapses identical numbers.

5.1 · total mismatch
987 654 321
href="tel:123456789" — text "987 654 321"
EXPECTED → two items: Call 123456789 and Call 987654321
5.2 · href full number, text a differently-formatted number
0123 456 7890
href="tel:+391234567890" — text "0123 456 7890"
EXPECTED → two items: Call +391234567890 and Call 01234567890
If the visible text contains any letters (e.g. "Ext. 3312") it is NOT recognised — only the href item appears. The text candidate must itself pass the recognition rule.
5.3 · DTMF pause in the href — known limitation
123 456 7890
href="tel:1234567890,,99" — DTMF pause + digits
EXPECTED → two items: Call 123456789099 (wrong — the comma and everything after it is merged into the number) and Call 1234567890 (from the text, correct)
Unlike ";" (truncated since v2.5.4), the DTMF "," is not cut at a boundary. Left to the softphone; dial the text item.

10 · tel: URI parameters (RFC 3966) — added in v2.5.4

Everything after the first ; in a tel: href (;ext=, ;phone-context=, ;isub=) is a parameter, not part of the number. Before v2.5.4 its digits were stripped of punctuation and merged onto the number. Now it is truncated — after the decode, so an encoded ; (%3B) is covered too.

10.1 · ;ext= — href param vs. plain text
+39 123 456 7890
href="tel:+391234567890;ext=99" — text "+39 123 456 7890"
EXPECTED → one item: Call +391234567890 (href param dropped → matches the text → deduplicated)
Before v2.5.4: two items, one of them Call +39123456789099
10.2 · ;phone-context=
123-4567
href="tel:1234567;phone-context=+39-012"
EXPECTED → one item: Call 1234567
Before v2.5.4: the context digits were merged into the number
10.3 · encoded semicolon (%3B)
Reservations
href="tel:%2B391234567890%3Bext%3D42" → decodes to "+391234567890;ext=42"
EXPECTED → one item: Call +391234567890 (truncation happens after decode)
10.4 · regression guard — no parameters
+39 123 456 7890

12 · Selection that carries a label — added in v3.0.1

Up to v3.0.0 a selection that dragged in the surrounding word produced no item at all: the anchored rule was tested against the whole string, letters included. Triple-clicking a line always hit this, because it grabs the paragraph. v3.0.1 splits the selection on spaces, drops word-only tokens, and rejects the lot if letters are glued to digits — so a label is ignored while a serial number is still refused. Select the whole line, label included.
