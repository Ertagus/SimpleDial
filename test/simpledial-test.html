5 · tel: link whose text number DIFFERS from the href

Key case: two distinct items are expected, no deduplication. This lets the user choose which number to dial — it is intentional, not a bug. Deduplication only collapses identical numbers.

5.1 · total mismatch
212 555 0148
href="tel:2125550111" — text "212 555 0148"
EXPECTED → two items: Call 2125550111 and Call 2125550148
5.2 · href full number, text a differently-formatted number
212 555 7042
href="tel:+12125557000" — text "212 555 7042"
EXPECTED → two items: Call +12125557000 and Call 2125557042
If the visible text contains any letters (e.g. "Ext. 3312") it is NOT recognised — only the href item appears. The text candidate must itself pass the recognition rule.
5.3 · DTMF pause in the href — known limitation
212 555 0188
href="tel:2125550188,,204" — DTMF pause + digits
EXPECTED → two items: Call 2125550188204 (wrong — the comma and everything after it is merged into the number) and Call 2125550188 (from the text, correct)
Unlike ";" (truncated since v2.5.4), the DTMF "," is not cut at a boundary. Left to the softphone; dial the text item.

10 · tel: URI parameters (RFC 3966) — added in v2.5.4

Everything after the first ; in a tel: href (;ext=, ;phone-context=, ;isub=) is a parameter, not part of the number. Before v2.5.4 its digits were stripped of punctuation and merged onto the number. Now it is truncated — after the decode, so an encoded ; (%3B) is covered too.

10.1 · ;ext= — href param vs. plain text
+1 212 555 0142
href="tel:+12125550142;ext=99" — text "+1 212 555 0142"
EXPECTED → one item: Call +12125550142 (href param dropped → matches the text → deduplicated)
Before v2.5.4: two items, one of them Call +1212555014299
10.2 · ;phone-context=
555-0187
href="tel:5550187;phone-context=+1-212"
EXPECTED → one item: Call 5550187
Before v2.5.4: the context digits were merged into the number
10.3 · encoded semicolon (%3B)
Reservations
href="tel:%2B12125550142%3Bext%3D42" → decodes to "+12125550142;ext=42"
EXPECTED → one item: Call +12125550142 (truncation happens after decode)
10.4 · regression guard — no parameters
+1 212 555 0158
href="tel:+1 212 555 0158"
EXPECTED → Call +12125550158 (unchanged — a plain number is not affected)
